# Обработка Testpilot: код, запросы, метаданные, пользовательские функции

С 1.7.0 сервер умеет открывать вместе с клиентом тестирования внешнюю обработку
`Testpilot.epf` и выполнять через неё BSL-код и запросы в клиентском и серверном
контексте, читать метаданные и вызывать пользовательские BSL-функции. Обработка
содержит два канала «запрос — результат» (клиентский и серверный); передача идёт через
форматированный документ, поэтому активная рабочая форма и её буфер ввода сохраняются.
Код исполняется в контексте служебной формы, а не в модуле произвольной открытой формы.

Источники upstream: [onec/Testpilot/README.md](https://github.com/ROCTUP/1c-testpilot/blob/main/onec/Testpilot/README.md)
и [CUSTOM_FUNCTIONS.md](https://github.com/ROCTUP/1c-testpilot/blob/main/onec/Testpilot/CUSTOM_FUNCTIONS.md).

## Настройка MCP

```dotenv
TC1C_CODE_EXECUTION=true      # инструмент tc_execute_code
TC1C_QUERY_EXECUTION=true     # инструмент tc_execute_query
TC1C_METADATA=auto            # auto: с кодом или запросами; true — независимо; false — скрыть
TC1C_FUNCTIONS=false          # два инструмента пользовательских функций
TC1C_CODE_EPF=onec/Testpilot/Testpilot.epf   # путь к обработке
TC1C_CODE_FORBIDDEN_WORDS=    # дополнительные запрещённые идентификаторы через запятую
TC1C_CODE_ALLOWED_WORDS=      # исключения из запретов, например: Записать,Write
```

Возможности включаются независимо; обработка запускается, если включена хотя бы одна.
Изменение настроек требует перезапуска MCP-сервера — агент не меняет их аргументами
вызова. В uv-пакете обработки нет: EPF скачивают с гита (`onec/Testpilot/Testpilot.epf`)
и кладут рядом с `.env`; в нашем стенде задан абсолютный путь
`TC1C_CODE_EPF=D:/Project/MCP/1c-testpilot/onec/Testpilot/Testpilot.epf`.

Путь относится к компьютеру запускаемого клиента 1С (абсолютный или от рабочего каталога
процесса). В профиле запуска можно переопределить параметром `code_epf`; относительный
путь в профиле считается от каталога YAML. Файл на удалённый компьютер автоматически
не копируется. В Python API путь включает обработку независимо от настроек публикации MCP.

## Запуск и подготовка

При `launch_client` сервер добавляет `/Execute`, подтверждает штатное предупреждение
безопасности только для указанного файла и проверяет версию протокола обработки;
подготовка входит в общий `wait`. Неудачная подготовка завершает запущенный процесс
и возвращает причину. Права пользователя 1С продолжают действовать: запрет внешних
обработок не обходится, неизвестный вопрос безопасности требует решения пользователя.

При `connect=false` запуск отвечает после открытия порта с `execution_ready=false`;
подготовка завершится при последующем `connect`. Подключение к чужому работающему
клиенту использует уже открытую `Testpilot.epf`; если её нет, обычные UI-действия
работают, а выполнение возвращает `helper_not_ready`.

## Инструменты

| Инструмент | Параметры | Результат |
|---|---|---|
| `tc_execute_code` | `code*`, `context*` (`client`/`server`), `parameters={}`, `timeout=180`, `connection_id` | `ok`, `request_id`, `result` либо ошибка |
| `tc_execute_query` | `query*`, `parameters={}`, `limit=100` (1–500), `timeout=180`, `connection_id` | `ok`, `request_id`, `columns`, `rows`, `returned_rows`, `limit`, `truncated` |
| `tc_get_metadata` | `name` либо `meta_type` + `search`/`field_search`; `sections`, `limit=100`, `offset=0`, `timeout=180`, `connection_id` | обзор, список или подробности; `complete`, `errors` |
| `tc_list_custom_bsl_functions` | `connection_id` | `functions`: описания зарегистрированных функций |
| `tc_execute_custom_bsl_function` | `name*`, `parameters={}`, `timeout=180`, `connection_id` | `ok`, `request_id`, `result` либо ошибка |

Инструменты функций видны, пока хотя бы у одного подключённого клиента есть непустой
реестр; `connection_id` выбирает клиент. Изменение доступности приходит как
`notifications/tools/list_changed`.

## Код

Параметры доступны в коде как соответствие `Параметры`; возвращаемое значение
присваивается `Результат`:

```json
{"context": "client", "code": "Результат = Параметры[\"текст\"] + \"!\";",
 "parameters": {"текст": "Проверка"}}
```

`context="client"` — клиентский контекст (открытые формы, интерфейс), `"server"` —
серверный (запросы, объекты, регистры). Один вызов — одна запись журнала действий;
во время записи XML-сценария выполнение отклоняется (в XML нет таких шагов).

## Запросы

Текст запроса и значения параметров передаются раздельно; параметры устанавливаются
через `Запрос.УстановитьПараметр` как данные:

```json
{"query": "ВЫБРАТЬ Код, Наименование ИЗ Справочник.Номенклатура ГДЕ Наименование ПОДОБНО &Имя",
 "parameters": {"Имя": "%чай%"}, "limit": 100}
```

- Выполняется запрос или пакет через `Запрос.Выполнить()`; возвращается результат
  последней выборки. В пакете можно `ПОМЕСТИТЬ` временные таблицы, использовать и
  `УНИЧТОЖИТЬ` их — всё одним значением `query`, в пределах одного вызова.
- `РАЗРЕШЕННЫЕ` добавляется автоматически к первому `ВЫБРАТЬ` каждого самостоятельного
  запроса пакета (в `ОБЪЕДИНИТЬ`-части — нет). Поддерживаются вложенные выборки и `ИТОГИ`.
- Итог ограничен 500 строками (ещё одна проверяется для `truncated`); лимит строк не
  ограничивает стоимость выполнения самого запроса.
- Результат учитывает права пользователя и RLS: пустая выборка не доказывает отсутствие
  данных, недоступных этому пользователю.

## Метаданные

```json
{}
{"meta_type": "Документ", "search": "заказ", "limit": 20, "offset": 0}
{"name": "Документ.ЗаказКлиента"}
{"name": "Документ.ЗаказКлиента.ТабличнаяЧасть.Товары"}
{"name": "Справочник.Номенклатура.СтандартныйРеквизит.Код"}
{"meta_type": "РегистрНакопления", "field_search": "Номенклатура", "limit": 50}
{"name": "Документ.ЗаказКлиента", "sections": ["fields", "table_parts"]}
```

Без фильтров — имя и версия конфигурации и количество объектов по видам; `meta_type`
выбирается из этого обзора. `search` ищет подстроку в имени или синониме объекта,
`field_search` — в имени или синониме поля. Списки отсортированы; `total` — число
совпадений, `truncated` — есть ли следующая страница. Для точного `name` возвращаются
`object` (однородные строки `fields` и `table_parts`: `name`, `title`, `kind`, `type`),
`types` (составляющие типов, объекты ссылок, квалификаторы числа/строки/даты), для
перечислений `values`, для основных типов `properties`. `sections` ограничивает
подробности: `fields`, `table_parts`, `values`, `properties`. Читается текущая
конфигурация с применёнными расширениями; вычисляемые колонки виртуальных таблиц не
перечисляются. Перед сбором серверный код включает привилегированный режим
(безопасный режим может ограничить его); исходный режим восстанавливается при успехе
и исключении. Частичные описания помечаются `complete=false` и содержат `errors`.

## Типы значений

Строки, числа, булевы, `null` (в 1С — `Неопределено`), массивы и объекты со строковыми
ключами передаются напрямую. Даты, ссылки и перечисления — типизированные JSON-объекты:

```json
{"Дата": {"$type": "date", "value": "2026-09-21T12:34:56"},
 "Товар": {"$type": "ref", "metadata": "Справочник.Номенклатура",
           "uuid": "fad620c2-c719-11e4-8ec3-bcaec56cc144"},
 "Ставка": {"$type": "enum", "metadata": "Перечисление.СтавкиНДС", "value": "НДС20"}}
```

Семейства ссылок: справочники, документы, планы видов характеристик/счетов/расчёта/обмена,
бизнес-процессы и задачи — `metadata` + `uuid`; перечисления — `metadata` + имя в `value`
(пустая ссылка — `value=""`); точки маршрута бизнес-процессов — `metadata` процесса +
имя точки в `point`; таблицы внешних источников и измерений кубов — `metadata` + штатный
`xml` ссылки. Полученный объект ссылки можно целиком передать обратно в `parameters`
следующего вызова (в коде, запросе или функции) — он станет исходной ссылкой 1С;
работает и внутри массивов/объектов, в обоих контекстах. Ответ содержит `presentation`,
но восстанавливается ссылка не из него. Неподдерживаемый тип даёт ошибку, а не строку.

## Ожидание и восстановление

`timeout` (1–3600 сек) — общий срок вызова; истечение не отменяет BSL и не означает, что
код не выполнился. После такого отказа следующий вызов сначала вернёт
`previous_execution_completed` с `previous_result` — переданный в нём новый код не
запускается. Служебная форма скрыта из обычного поиска и обхода: чтение, запись, нажатие,
закрытие и захват её экрана запрещены общим обработчиком и транспортом. Закрытие всей 1С
разрешено. Ожидание очереди к занятому соединению ограничено `TC1C_QUEUE_TIMEOUT=60`;
`list_connections` показывает `busy`, `active_action`, `active_seconds`.

## Запреты в произвольном коде

По умолчанию запрещены идентификаторы: `Удалить`, `Delete`, `Записать`, `Write`,
`УстановитьПривилегированныйРежим`, `SetPrivilegedMode`, `ПодключитьВнешнююКомпоненту`,
`AttachAddIn`, `УстановитьВнешнююКомпоненту`, `InstallAddIn`, `COMОбъект`, `COMObject`,
`УстановитьМонопольныйРежим`, `SetExclusiveMode`, `УдалитьФайлы`, `DeleteFiles`,
`КопироватьФайл`, `CopyFile`, `ПереместитьФайл`, `MoveFile`, `СоздатьКаталог`,
`CreateDirectory`. Проверяются целые идентификаторы без учёта регистра; комментарии и
строковые литералы пропускаются. Отказ `forbidden_code` содержит идентификатор и строку,
команда в 1С не отправляется. `Выполнить`, `Execute`, `Вычислить`, `Eval` запрещены всегда.
Фильтр — не песочница: вызванная процедура конфигурации может менять данные без
запрещённых слов в переданном тексте. Для доступа «только запросы» включай один
`TC1C_QUERY_EXECUTION`.

## Пользовательские BSL-функции

Реестр функций находится в двух последних областях модуля формы обработки —
`РегистрацияПользовательскихФункций` и `ПользовательскиеФункции` (в поставляемой EPF
он пуст). При обновлении обработки весь блок между «ПОЛЬЗОВАТЕЛЬСКИЕ ДОРАБОТКИ» и
«КОНЕЦ ПОЛЬЗОВАТЕЛЬСКИХ ДОРАБОТОК» переносят в новый модуль и пересобирают EPF.

```bsl
&НаКлиентеНаСервереБезКонтекста
Функция РеестрПользовательскихФункций()
    Функции = Новый Массив;
    Аргументы = Новый Массив;
    Аргументы.Добавить(ОписаниеПараметраФункции(
        "числа", "array", "Числа, которые нужно сложить", Истина));
    ЗарегистрироватьПользовательскуюФункцию(Функции,
        "СложитьЧисла", "Вычисляет сумму переданных чисел",
        "server", "СуммаЧисел", Аргументы, "Число — итоговая сумма");
    Возврат Функции;
КонецФункции

&НаСервере
Функция СуммаЧисел(Аргументы)
    Сумма = 0;
    Для Каждого Значение Из Аргументы["числа"] Цикл
        Сумма = Сумма + Значение;
    КонецЦикла;
    Возврат Сумма;
КонецФункции
```

`ЗарегистрироватьПользовательскуюФункцию(Реестр, Имя, Описание, Контекст, Обработчик,
Аргументы, ОписаниеРезультата)`; контекст `client` или `server`, у клиентской функции
директива `&НаКлиенте`. `ОписаниеПараметраФункции(Имя, Вид="any", Описание="",
Обязательный=Ложь, ЗначениеПоУмолчанию=Неопределено)`; виды: `string`, `number`,
`boolean`, `array`, `object`, `date`, `ref`, `enum`, `any`. Обработчик принимает один
аргумент типа `Соответствие` (ключи — имена параметров регистрации) и возвращает
значение поддерживаемого формата; `Экспорт` не требуется.

Вызов: `tc_execute_custom_bsl_function` с `{"name": "СложитьЧисла",
"parameters": {"числа": [10, 20, 30]}}` → `ok=true, result=60`. Для MCP нужен
`TC1C_FUNCTIONS=true` и путь к своей EPF; в Python методы доступны при запуске клиента
с обработкой без публикационных настроек. Функции выполняются с правами текущего
пользователя; фильтр запрещённых слов проверяет только код, переданный агентом.

## Python

В профиле: `code_epf: 'путь/к/Testpilot.epf'`; в коде: `launch_client(..., code_epf=...)`;
через окружение: `TC1C_CODE_EPF` (приоритет: аргумент → профиль → окружение;
`code_epf=""` — без обработки). Методы: `execute_code`, `execute_query`, `get_metadata`,
`list_custom_bsl_functions`, `execute_custom_bsl_function` — ошибки через `ActionError`,
результаты — обычные словари и списки (без TOON).

## Сборка своей EPF

`python onec/Testpilot/build.py --exe "<путь>/1cv8.exe" --base "<файловая база>"` —
использует конфигуратор установленной платформы и существующую файловую базу,
конфигурация базы не изменяется. Готовая EPF проверена на 8.3.27.1936 и 8.5.1.1343.
